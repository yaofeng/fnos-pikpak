# 统一账号作用域（v2.1.0）设计

日期：2026-11-25
状态：待用户批准
前置：多账号绑定已上线（2.0.0，specs/2026-11-24-multi-account-design.md）

## 意图与为什么

2.0.0 里账号维度是割裂的：「我的文件」「回收站」一次只看一个账号（下拉切换），
其余列表页（最近、离线任务、传输）永远合并全部账号。用户要在两种心智模型之间
来回切换，且合并视图恰恰在文件最多的两个页面上缺失。2.1.0 统一为一套逻辑：

> 每个内容页都有同一个账号下拉框，选项为固定的「-全部帐号-」+ 各账号。
> 选「-全部帐号-」时服务端合并所有账号的内容；进子目录时只合并**同路径**
> 存在该目录的账号，其余忽略；文件悬浮提示以「@帐号名」后缀区分来源。

## 目标 / 非目标 / 反目标

目标：

1. 五个内容页（我的文件、回收站、最近、离线任务、传输）统一挂同一账号下拉框，
   含固定「-全部帐号-」选项。
2. 合并视图：服务端并行列目录、按行打账号戳、每账号独立分页与错误隔离。
3. 我的文件合并视图支持进子目录，按**同名路径**跨账号合并。
4. 合并行的悬浮提示追加「@帐号名」。
5. 双语（zh-CN/en）完整覆盖新增文案。

非目标：

- 分享类页面（全网搜索、分享收藏夹、视频收藏夹、分享浏览）不加账号维度——
  它们工作在单一身份或本地收藏存储上，没有"按账号浏览"的语义。
- 合并视图中的新建文件夹、上传、拖拽移动/复制、清空回收站（用户已拍板禁用）。
- 搜索结果页的跨账号搜索。
- 跨账号去重（同名文件合并为一行）——同名文件各占一行，靠 @后缀区分。

反目标（做错即失败）：

- 合并视图里任何一个账号的失败（重新授权、限流、网络）拖垮整个列表。
- 单账号视图的行为发生任何变化（缓存、请求、操作语义与 2.0.0 一致）。
- 「-全部帐号-」选择在刷新/重进后丢失或落到某个具体账号。

## 约束

- 身份永远来自 `fnos.IdentityFrom`；账号参数只决定作用域，不引入身份。
- 不新增 Go/npm 依赖。
- 新增文案全部进 `web/src/i18n.ts`（zh-CN + en），无硬编码中文。
- 版本升级 2.0.0 → 2.1.0（manifest、Makefile `VERSION`、release tag）。
- Go 全量测试 + 前端 vitest 全量通过；oxlint 警告不新增。

## 方案取舍

### 子目录「同路径」解析（核心难点）

PikPak 文件对象只有 `parent_id`，没有路径字段。「账号 B 在同一路径下的同名
文件夹」必须按名字解析。三个方案：

- **A. 服务端同名路径解析（选定）**：合并模式下前端请求带 `path=/a/b`；
  服务端对每个账号从根目录按名字逐级 `ListFiles` 找到同名文件夹（会话内
  缓存 id，TTL 5 分钟），解析不到该名字的账号**直接跳过**，然后并行列出
  各账号解析到的文件夹、合并返回。前端每级导航一个请求。
  代价：首次到达某路径时每账号多 depth 次上游调用（有缓存）；收益：前端
  零解析逻辑、上游调用在服务端并行、解析失败天然退化为"该账号被忽略"。
- **B. 浏览器端解析**：前端逐账号发请求自行走名字。请求轮次多、时序复杂、
  移动端弱网体验差。弃。
- **C. 仅根目录合并**：进子目录只显示该文件夹所属账号。最便宜但直接违背
  需求（用户明确要求子目录同路径合并）。弃。

### 合并视图中的创建型操作

- **禁用（选定，用户拍板）**：新建文件夹/上传/拖拽移动/复制/清空回收站只在
  选定具体账号时可用。合并视图里这些操作的"目标账号"没有自然答案，猜测
  （默认第一个账号）会造成文件落到错误账号；清空回收站会波及所有账号。
- 默认建到某账号：被否——静默选择违背多账号隔离的直觉。

## 设计

### 1. 作用域模型（前端）

- `AccountContext` 扩展：`wanted` 取值 `'' | 'all' | <accountId>`。
  `scope`（对外）= `wanted || 'all'`；`currentId` 仅在 `wanted` 是真实账号 id
  时有意义。`resolveCurrentId` 的"落到第一个账号"兜底只对单账号作用域生效，
  `'all'` 不参与兜底（未绑定账号时列表页已有 not_bound 处理）。
- `AccountSwitcher` 增加 `scope` 模式：选项为 `-全部帐号-`（value `all`）+
  各账号（value id）；`onChange('all' | id)`。账号数 < 2 时仍不渲染
  （单账号用户"全部"与"唯一账号"等价，无需选择）。
- 五页挂载同一下拉框，选择保存在 AccountContext（进程内，与 2.0.0 一致）。
- 我的文件、回收站默认落 `'all'`（统一逻辑的直接体现）；最近/离线任务/
  传输本来就合并，默认 `'all'` 行为不变。

### 2. 服务端合并列表

所有列表 handler 在解析 `?account=` 前**先判 `all` 哨兵**（现实现会把
`all` 当账号 id 去 store 查而 404）：

| 路由 | 现状 | 2.1.0 |
|---|---|---|
| `GET /api/files` | 单账号 | `account=all`（+`seg` 路径段）→ 合并；其余单账号不变 |
| `GET /api/trash` | 单账号 | `account=all` → 合并；其余单账号不变 |
| `GET /api/tasks` | 永远合并 | 新增 `account=<id>` 单账号过滤；`all`/缺省 = 合并 |
| `GET /api/downloads` / `GET /api/uploads` | 本机任务库按 uid 存储，行带 `account_id` 戳，**无账号参数** | 无 API 改动；传输页下拉框在**前端按行 `account_id` 过滤**（builder check 修正：此前误写为 `GET /api/transfers` 支持 `?account=`） |
| `GET /api/recent` | 永远合并 | 新增 `account=<id>` 单账号过滤；`all`/缺省 = 合并 |

- 合并实现复用 merge.go 基建：`allAccountClients`（只含 active 账号，
  会话失败的账号静默缺席）+ 每账号并行拉取 + `encodePageToken` 每账号
  分页信封 + `account_errors` 单账号错误上报。
- files/trash 新增并行拉取器（`fetchListPages`，对 `ListFiles` 版的
  `fetchFilePages`），合并排序沿用 `modifiedSortKey`（时间倒序，服务端
  保证稳定；客户端仍按用户所选键重排已加载页——与现状一致）。

#### 离线任务页的作用域语义（已确认，2026-11-25）

下拉框 = 该页所有操作的账号作用域（用户已拍板）：

- **创建**：选定具体账号 X 时，`POST /api/tasks` 带 `?account=X`
  （端点已支持指定账号），配额轮换只在 `-全部帐号-` 下继续——轮换的意义
  就是把配额摊到"所有账号"上；筛选到 X 却建到别的账号，列表和提示都会
  自相矛盾。
- **清除已完成**：按当前作用域清理——X 只清 X 的已完成任务，`-全部帐号-`
  保持现状（所有 active 账号，现有确认弹窗文案不变）。清除端点需新增
  `?account=` 参数支持（现固定遍历全部账号）。
- `pikpak.File` 增加 `AccountName string json:"account_name,omitempty"`；
  `stampFiles` 同时打 `AccountID` + `AccountName`（对齐 `stampTasks`），
  前端提示无需再查表。
- `q`（本地名字过滤，`q_local=true`）与 `kind` 过滤在合并模式下对合并后
  页面逐账号应用后合并，语义不变。

### 3. 子目录同名路径解析（方案 A）

- 新增 `GET /api/files?account=all&seg=a&seg=b&...`：路径以**重复的 `seg`
  查询参数**表达（每段一个名字，按出现顺序）。不用拼接字符串 split `/`：
  PikPak 对文件名里是否允许 `/` 从未验证过，拼接契约在含 `/` 的名字上
  有歧义；段列表契约无论上游规则如何都无歧义。前端栈直接持有名字数组，
  不拼接、不切分。
- 对每个账号从根（`parent_id=""`）逐段 `ListFiles` 找 `kind=folder` 且
  `name` 精确匹配（非前缀、非模糊）的子项；任一段找不到 → 该账号本路径
  无此目录，跳过。
- 根目录：无 `seg` 参数 = 各账号根并列目录。
- 解析缓存：进程内键为 `(uid, accountID, segments)`，segments 以 JSON
  序列化进键（避免含 `/` 名字在键上歧义），值 folderID；TTL 5 分钟，
  并发安全（单 mutex 足够，NAS 规模）。缓存命中不省列表调用，只省
  解析走查；过期重解析天然吸收改名/删除。
- 行所属账号：解析到的文件夹行与文件行都带 `account_id/account_name`。
- 合并分页：`page_token` 信封按账号 id 键控（每账号在本路径恰好解析出
  一个文件夹，键不冲突），复用 `pageDone` 哨兵。
- 失败面：某账号列表调用失败 → `account_errors` 一条，其余账号正常；
  全部失败 → 仍是 200 + 全部行缺失 + `account_errors`（与 recent 一致，
  不整体 5xx）。
- 解析走查中的上游失败等同"该账号无此目录"（跳过），不进 `account_errors`
  ——解析失败只影响该账号缺席，不告警。

### 4. 前端我的文件/回收站合并模式

- 请求：`scope==='all'` 时 `GET files?account=all&path=<栈上名字拼接>`
  （回收站无 path）；单账号模式请求串与 2.0.0 逐字节一致。
- 面包屑：合并模式栈存 `name`（导航按 path 前缀截断）；单账号模式栈存
  `{id,name}`（现状不变）。`Crumb` 增加 `accountId?` 标记来源账号仅用于
  合并模式点击进入时拼 path（id 不再是导航键）。
- 缓存键：`cacheKeys.files(scope, folderKey, kind)`，合并模式
  `folderKey='path:'+path`，单账号 `folderId`（现状）。回收站同理。
- **禁用矩阵**（`scope==='all'`，按钮渲染为 disabled + 说明 title）：
  新建文件夹、上传、下载按钮之上的拖拽移动/复制（move/copy 弹层入口）、
  右键菜单中的移动/复制/重命名入口保留（重命名/删除是行内操作）——
  移动/复制菜单项禁用；清空回收站按钮禁用。删除（移入回收站/永久删除）、
  下载、重命名、播放按行内账号执行。
- 跨账号多选删除：按 `account_id` 把选中行分组，逐账号发既有
  `?account=` 操作请求，聚合计数后提示。
- 合并行操作请求带行上 `account_id`（操作端点已是 `?account=` 作用域，
  无后端改动）。

### 5. 悬浮提示「@帐号名」

- 列表视图（FileTable）名字单元格 `title`、大图标视图（FileGrid）tile
  `title`：行带 `account_name` 时追加 `@${account_name}` 后缀；无戳行
  （单账号视图）不加。格式字面 `@`，不入 i18n 表。

### 6. 下拉框文案

- `-全部帐号-`：zh-CN `-全部帐号-`，en `- All accounts -`（两侧横线
  保留，作为"固定合成选项"的视觉标记，与真实账号名区分）。
- 禁用操作的 title 各一条 i18n 键（如 `files.merged_readonly`）。

### 7. 版本与交付

- `Makefile` `VERSION ?= 2.1.0`、manifest `version=2.1.0`、
  release tag `v2.1.0`。
- 交付管线不变：`make fpk` → 拷贝 remote/fn-private → `gh release`。

## 留给实施者的决定

- 解析缓存的具体容器与过期扫除方式（map + 时间戳惰性过期即可）。
- `fetchListPages` 与 `fetchFilePages` 的合并方式（泛型或复制，倾向复制
  保持 merge.go 的直白风格）。
- Files.tsx 内 scope 分支的组织（现有 effect 已按 accountId 分缓存，扩展
  而非重写）。

## Review Focus（实施计划里要落成测试的失效模式）

1. **同路径解析错了账号**：名字匹配必须精确（非前缀/非模糊），`kind`
   必须是 folder；解析缓存键漏 uid 会跨用户串目录——单测覆盖。
2. **`all` 哨兵漏改**：五个路由都要在 `accountForParam` 之前分流，漏一处
   就是 404「账号不存在」——每路由一条 handler 级测试。
3. **单账号请求串漂移**：2.0.0 的单账号行为（缓存键、`?account=`、分页）
   必须逐字节不变——现有测试全部保持绿。
4. **合并分页信封键冲突/重复行**：pageDone 哨兵在 files/trash 合并模式下
   的行为与 recent 一致——翻页测试覆盖不重复、不重启。
5. **合并视图禁用矩阵**：每个创建型入口在 `all` 下真实不可达（按钮
   disabled、右键菜单项禁用、drop 目标拒绝）——前端逻辑单测 + 冒烟清单。

# PikPak M0 安装与验证说明

M0 是一个**诊断版**：它不提供完整的文件管理界面，只负责在真机上验证设计里的六个未决前提，并把结果导出成一份报告。请在飞牛 NAS 上按下面的步骤安装并运行。

安装包路径：`dist/pikpak-0.1.0-x86.fpk`（版本号必须是 `x.y.z` 形式，所以 M0 也记为 `0.1.0`，M0 只体现在应用描述里）。

## 1. 把安装包传到飞牛

任选一种：

- **文件管理器**：通过飞牛的 SMB / WebDAV / 文件管理把 `.fpk` 上传到任意目录（例如 `个人空间/下载`）。
- **SSH / scp**（如已开启 SSH）：

  ```bash
  scp dist/pikpak-0.1.0-x86.fpk <用户名>@<飞牛地址>:/tmp/
  ```

## 2. 安装

1. 打开飞牛桌面 → **应用中心**。
2. 右上角菜单选择 **手动安装**（或"安装本地应用"），选中 `.fpk` 文件。
3. 等待安装完成。应用名显示为 **PikPak**，描述带"（M0 验证版）"。

> 注意：本包用 `fnpack build --nosign` 构建，没有开发者签名。如果飞牛提示"未签名/来源不受信任"，需要允许安装第三方应用或改用带签名的包。若系统直接拒绝，请把提示原文记入报告（这本身也是 M0 要确认的事项之一）。

安装后文件位置（供排查用）：

| 内容 | 典型路径 |
|---|---|
| 程序 | `${TRIM_APPDEST}`，一般形如 `/var/apps/pikpak/target` |
| 数据（SQLite、密钥、日志） | `${TRIM_PKGVAR}`，一般形如 `/var/apps/pikpak/var` |
| 日志 | `${TRIM_PKGVAR}/logs/app.log`，一般形如 `/var/apps/pikpak/var/logs/app.log` |

具体路径以飞牛实际挂载为准；`cmd/main` 启动时会使用这些环境变量。

## 3. 打开应用

在飞牛桌面点击 **PikPak** 图标。应用通过统一网关挂载在 `/app/pikpak`，页面里依次是：

1. **服务状态**：版本号与当前飞牛用户 UID。
2. **PikPak 账号**：绑定入口。
3. **网关信息**、**Range 探针**、**上传探针**、**文件授权探针**、**探针**。

## 4. 绑定 PikPak 账号

1. 在 **PikPak 账号** 卡片点 **绑定 PikPak**。
2. 页面显示用户码和一个 `mypikpak.com` 链接；用浏览器打开链接并确认用户码。
3. 页面每 1.5 秒轮询一次，授权成功后显示"已绑定"。

每个飞牛用户各自绑定、各自保存凭据（AES-256-GCM 加密存于 SQLite），互相不可见。解绑请点 **解绑**。

> 绑定使用 OAuth 设备码，不是个人访问令牌（PAT）。原因：PAT 无法获得 `files:purge`，清空回收站只能走 OAuth。

## 5. 运行探针并导出报告

1. 打开 **探针** 卡片，点 **运行全部探针**。
2. **文件授权探针** 需要手动点一次 **选择飞牛目录**，在飞牛文件选择器里选一个目录，确认"可写"结果。
3. **网关信息** 里点 **伪造身份头测试**，记录结果。
4. **Range 探针** 点 **测试 64 MiB 文件**，观察首字节耗时与总耗时。
5. **上传探针**：
   - 点 **上传生成文件（20 MiB）**，这是后端自己生成的确定性文件，用来验证 GCID + OSS 分片链路。
   - 也可点 **上传飞牛文件** 选择自己的文件；后端会先校验该路径在当前用户的授权目录内且可读。
   - "目标文件夹 id"留空表示上传到 PikPak 根目录。
6. 点 **导出报告**，浏览器会下载 `pikpak-m0-report.json`，复制保存。

报告里不会出现 token、设备码或签名下载地址（已脱敏）；如果发现疑似敏感字段，请直接反馈，不要外传原始文件。

## 6. 填写结论

按 [`docs/m0-report.md`](m0-report.md) 的表格逐项填写，把 JSON 报告里的对应字段贴进去。八个结论都明确后，才进入 M1 计划。

## 7. 查看日志与卸载

查看日志：

```bash
tail -n 200 /var/apps/pikpak/var/logs/app.log
```

日志只记录生命周期与错误，不记录令牌。

卸载：**应用中心 → 已安装 → PikPak → 卸载**。卸载会删除 `${TRIM_PKGVAR}` 下的数据（数据库与密钥），需要重新绑定。

## 8. 排障

| 现象 | 处理 |
|---|---|
| 页面空白或 404 | 确认通过飞牛桌面打开（走 `/app/pikpak` 网关），而不是直接访问端口 |
| 接口返回 401 | 网关没有注入 `X-Trim-Userid`；确认从桌面内打开应用 |
| 接口返回 400 且提示身份头重复 | 网关保留了客户端伪造的 `X-Trim-Userid`；这是安全拦截，属预期行为，请记录到报告 |
| 绑定页一直"等待授权" | 用户码 5 分钟后过期；点"重试"重新发起 |
| 上传 403 | 选择的文件不在当前飞牛用户的授权目录内，或没有读权限 |
| 探针显示"未绑定 PikPak 账号" | 先完成第 4 步 |

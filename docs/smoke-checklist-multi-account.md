# 多账号 + 页面保活 手工冒烟清单（2026-11-25）

> 来源：multi-account 分支 Task 12 全量验证报告。验收方式：`make dev` 后浏览器打开 http://127.0.0.1:8787 按序执行；真机安装包版本见 dist/。

## 用户手工冒烟清单（make dev 后浏览器打开 http://127.0.0.1:8787，按序执行）

**准备**：`make dev`，浏览器打开 `http://127.0.0.1:8787`，确保只绑定一个 PikPak 账号。

### A. 单账号反目标自检

1. 只有一个账号时，顶栏不出现账号切换器，文件/最近/传输/回收站各页表现与升级前一致。
2. 直接访问 `/` 自动跳转到 `/files`；访问任意未知路径（如 `/foobar`）落到 `/files`。

### B. 绑定第二账号与切换隔离

3. 在设置页绑定第二个 PikPak 账号 → 顶栏出现账号切换器。
4. 在账号 A 进入某个非根目录文件夹 → 切换到账号 B → B 的根目录正常渲染并保持稳定（不闪「这个文件夹是空的」，无报错闪烁）。
5. 切换账号后，文件/最近/传输/回收站各列表显示的是当前账号的数据，条目带所属账号徽章，两个账号的内容互不串号。
6. 在 `/search` 输入关键词出结果 → 切换账号 → 搜索框关键词被清空（账号间搜索态隔离）。

### C. 合并页与账号徽章

7. 「最近」「传输」「离线任务」三页合并显示所有账号的数据，每条带所属账号徽章，可分辨来源账号。

### D. 离线任务

8. 新建一个离线下载任务 → 提示明确指出该任务命中（或随机选中）的账号名字。

### E. 分享与播放

9. 打开一个分享链接走完整播放流程：若分享副本已存在于任一账号则直接复用、不转存；否则自动转存进（随机）账号并提示转存到的账号名。
10. 切到非默认账号，播放一个视频 → 播放正常开始，播放页 URL 带 `account=` 参数。

### F. Keep-alive 页面状态

11. `/search` 输入关键词出结果 → 切到 `/files` → 返回 `/search`：关键词与结果仍在。
12. `/files` 长列表滚动到中部 → 切走再返回：滚动位置保留。
13. `/transfers` 深度滚动 → 切到 `/tasks`（页面很短）→ 返回 `/transfers`：滚动位置保留（重点回归项，此处曾是真 bug）。
14. 各页面仅在首次访问时挂载；再次切回不重新闪加载态，缓存即时回放（可在 Network 面板确认无重复首屏请求）。
15. 停留在 `/files` 等非传输页时，Network 面板中传输轮询暂停；返回 `/transfers` 轮询立即恢复且先回放缓存数据。
16. 浏览器前进/后退正常；直接深链打开 `/files/folder-x` 能进入对应文件夹。
17. 按 F5 刷新 → 页面状态不恢复（回到默认视图）——这是设计预期，不算缺陷。

### G. 旧数据升级

18. 参考 Task 1 fixture 思路，手工造一份旧版 `.data` 目录后启动 → 旧账号自动出现在切换器中并可正常使用。

**全部通过即验收；任何一项不符 → 按 systematic-debugging 处理，并重跑对应任务的测试。**

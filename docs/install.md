# PikPak for fnOS 安装与验证

面向 fnOS（飞牛）x86 设备的安装说明。应用装在飞牛上，通过桌面图标打开；每个飞牛用户绑定自己的 PikPak 账号，互相看不到对方的文件。

安装包：`pikpak-<版本>-x86.fpk`（例如 `pikpak-1.0.0-x86.fpk`），来自 [Releases](../../releases) 或本地 `make fpk`。

## 1. 把安装包传到飞牛

任选一种：

- **文件管理器**：通过 SMB / WebDAV / 飞牛文件管理把 `.fpk` 上传到任意目录（例如 `个人空间/下载`）。
- **SSH / scp**（如已开启 SSH）：

  ```bash
  scp dist/pikpak-1.0.0-x86.fpk <用户名>@<飞牛地址>:/tmp/
  ```

## 2. 安装

1. 飞牛桌面 → **应用中心** → 右上角菜单 → **手动安装**，选中 `.fpk`。
2. 应用名显示为 **PikPak**。
3. 若提示"未签名 / 来源不受信任"：本仓库未配置开发者证书时构建的包不带签名，需要在飞牛里允许安装第三方应用，或改用带签名的包（仓库 Secrets 配好 `FN_DEVELOPER_KEY` / `FN_DEVELOPER_CERT` 后由 CI 签名）。

安装后的位置（排查用，以飞牛实际挂载为准）：

| 内容 | 典型路径 |
|---|---|
| 程序 | `${TRIM_APPDEST}`，形如 `/var/apps/pikpak/target` |
| 数据（SQLite、密钥、日志） | `${TRIM_PKGVAR}`，形如 `/var/apps/pikpak/var` |
| 日志 | `${TRIM_PKGVAR}/logs/app.log` |
| 本地通信 | `${TRIM_APPDEST}/app.sock`（0600，不监听 TCP） |

## 3. 打开应用

从飞牛桌面点击 **PikPak** 图标。页面挂载在统一网关下（`/app/pikpak`），左侧是功能导航：

**我的文件 · 最近 · 回收站 · 传输 · 离线任务 · 分享收藏夹 · 视频收藏夹 · 全网搜索**（设置在最下方）

> 必须通过飞牛桌面打开。直接访问端口或把地址发给别人不会工作：身份只认飞牛网关注入的 `X-Trim-Userid`。

## 4. 绑定 PikPak 账号

首次打开会提示"尚未绑定 PikPak 账号"：

1. 点 **绑定账号**（或进 **设置 → 账号 → 重新授权**）。
2. 页面显示用户码和 `mypikpak.com` 链接；用浏览器打开链接并确认用户码。
3. 页面自动轮询，授权成功后显示"已绑定"。

凭据用 AES-256-GCM 加密存在本机 SQLite，只属于当前飞牛用户。绑定使用 OAuth 设备码而不是个人访问令牌，因为清空回收站需要 OAuth 才能拿到的 `files:purge` 权限。

## 5. 常用功能

### 文件

- 浏览、进入文件夹、面包屑返回、大图标/列表切换（默认大图标，和 fnOS 文件管理一致）。大图标下名字下面不再有类型/大小一行：文件夹只显示名字，文件的大小以右下角的小标签叠在图标上。
- 选择按 Finder 的规则：单击单选，`Command`（Mac）/ `Ctrl`（Windows）单击切换多选，`Shift` 单击选一段，在空白处拖动框选，`Command/Ctrl + A` 全选，`Esc` 取消。
- 新建文件夹、重命名、移动（拖拽或右键菜单）、复制、删除：工具栏的**删除**先弹确认窗口，由你选**移入回收站**还是**永久删除**（跳过回收站、不可恢复）；右键菜单里的**移入回收站**已经指明方式，直接执行。
- 名称筛选与类型筛选只作用于已加载的条目；列表接口不支持服务端排序/搜索，这一点在页面底部有说明。搜索整个 PikPak 账号请用 **全网搜索**。

### 离线任务

- 新建：粘贴磁力链接或 URL，等 PikPak 云端下载完成。
- 按状态筛选、重试失败任务、删除任务（可勾选同时删除已下载文件，默认不勾）。
- 每日离线额度用完时显示"离线任务每日额度已用完，请明天再试"，不会自动重试。

### 传输

- **下载到…**：把 PikPak 文件下载到飞牛上的目录。只能写当前飞牛用户有权限的目录（文件选择器或绝对路径）。
- **上传**：从飞牛目录选文件上传到 PikPak 当前目录。
- 传输页显示进度、速度、剩余时间；可暂停/继续/取消；重名策略在设置里选（重命名 / 跳过 / 覆盖）。
- 同时下载数由全局并发上限控制（默认 2，最高 4）。

### 回收站

- 列出、还原、永久删除单个文件，或清空回收站。

### 播放

- 文件菜单里对视频点 **播放**：内置播放器支持全屏、0.5×–2× 倍速、下载。
- 默认走**代理**模式：签名下载地址只留在后端，浏览器拿到的是本站地址，拖动进度条由 CDN 按 Range 响应。
- 不做转码。浏览器不支持的编码（常见如部分 MKV 封装）会明确提示"浏览器不支持该编码，可下载后使用本地播放器观看"。

### 全网搜索

- 通过搜索引擎查找 `mypikpak.com` 上的**公开分享页**。只输入关键词即可，`site:` 限定由服务端自动拼接。
- 依赖一个搜索服务 API Key（默认 Serper，返回 Google 结果）：在 **设置 → 参数设置 → 全网搜索 API Key** 里填写，可在 serper.dev 免费申请。Key 只存在本机数据库，读取设置时不会返回，也不会写进日志。
- 结果在应用内标签页打开（标题栏下方出现标签页，可关闭、可切换回“搜索结果”），不再跳到浏览器；右键标签页可以复制地址、加入收藏。
- 服务端一次只查一个分享域名（`mypikpak.com`），只有它没有结果时才依次换 `mypikpak.net`、`pikpak.me`、`mypikpak.me`，不会一次查多个域名；每页请求 20 条，最多 10 页；每次翻页都会消耗一次搜索服务的额度。搜索引擎只收录公开分享，自己账号里**未分享**的文件和文件夹搜不到。
- 结果**滚动到底自动加载下一页**并接在已有结果后面（没有“上一页/下一页”按钮）；一页内容不足以填满窗口时也会继续加载，直到填满或没有更多结果，列表底部显示“没有更多结果了”。

### 分享浏览与收藏夹

- 点开搜索结果后，标签页里是**原生分享浏览器**，布局与 **我的文件** 一致：面包屑、当前目录筛选、工具栏、排序、大图标/列表切换、状态栏。
- 如果分享的**根目录只有一个文件夹**，浏览器会直接进入这个文件夹，跳过没有任何选择的根目录；此时面包屑和「上一级」都不能回到根目录（要离开就回收藏夹或搜索页）。
- 带密码的分享会先要访问密码；密码只在打开时交给服务端，之后浏览、预览、完整播放、转存都用服务端缓存的会话（2 小时），密码不会回到浏览器。
- 选择规则与 **我的文件** 相同（单击、`Command/Ctrl`、`Shift`、框选、`Command/Ctrl + A`）。
- 工具栏：**预览** 和 **完整播放** 作用在单个视频上（区别见下一节）；**转存** 把选中项存到 PikPak **我的文件根目录**；**下载** 先把选中的视频转存到 **Pack From Shared**（已有副本直接复用），再加入下载队列；**收藏视频** 把选中的视频加进视频收藏夹。**双击视频 = 完整播放**。
- 收藏这条分享用**地址栏右侧的星标**（和浏览器收藏一样）：实心表示已收藏，再点一次取消收藏；它不在工具栏里占位置。
- **分享收藏夹**（导航中在 **视频收藏夹** 上方）与 **我的文件** 用同一套布局：导航行（刷新、标题、筛选）、工具栏、文件表格和底部状态栏。表格列出**分享名称、创建者（头像 + 昵称）、总文件数、总大小、分享时间、过期时间**；双击一行进入分享，不需要再输密码。
- 表格用 Finder 的选择方式（单击、`Command/Ctrl`、`Shift`、全选）；工具栏的 **重命名** 和 **删除** 作用在选中的行上，不再挂在每一行。重命名只改本机显示名。工具栏右侧的**排序**可以按分享名称、创建者、总文件数、总大小、分享时间、过期时间升/降序排列（默认按收藏时间）；还没统计出的数字和空的创建者始终排在最后。**新增收藏** 可以把一条分享链接（带 `?pwd=` 访问密码也可以）直接加进来，不必先打开；删除收藏不影响原分享。收藏存的是**分享编号**而不是整条链接；旧版本存下的链接会在下次打开这个页面时自动改写成编号（密码保留）。
- PikPak 不直接给分享的总文件数和总大小，只有根目录条目数，所以这两个数由服务端**遍历分享目录后统计**并存在本机。**打开分享收藏夹只读缓存，不发起统计**：没统计过的分享显示「—」（悬停提示「进入分享后自动统计」）。**进入某个分享时**，如果它还没有统计结果、或者结果超过 1 天，服务端会在后台重新统计并写回缓存，下次回到列表即可看到；点 **刷新** 只重新读缓存。打不开或条目过多的分享显示「—」并提示「无法统计这个分享」。头像同样由服务端代理，CDN 地址不出后端。
- 分享里的视频在**大图标左下角**有两个状态角标（白底圆形、与边角留出间距）：**金色星标**表示已在**视频收藏夹**里；**绿色对勾**表示 **Pack From Shared** 里已有这个名字和大小的副本（完整播放会直接用）；两者都有时显示星标（已收藏优先）。删除副本后对勾会随列表刷新消失。列表视图把同一个图标放在文件名前面。
- 从收藏夹打开的分享视图，面包屑左侧有**主页**图标，一步回到收藏夹列表。
- 分享里的文件不经过「传输」队列——队列按 PikPak 网盘文件编号工作，分享文件不在其中；要长期保留请用 **转存** 或 **完整播放**。

### 视频收藏夹

- 在分享浏览器里选中一个或多个视频点 **收藏视频**：分享编号、文件编号、分享者与访问密码都随收藏保存在本机数据库，之后不用再回分享里翻。
- 导航 **视频收藏夹**（**分享收藏夹** 下方）列出收藏的视频，按**分享者**分组（分享创建者的昵称；没有就用分享标题；都没有就是「未知分享」），组内按收藏时间倒序。
- 显示方式与 **我的文件** 一致：默认大图标，可切列表；缩略图经后端 `/api/thumb` 代理，签名地址不出后端。大图标尺寸在 **设置 → 参数设置 → 大图标尺寸** 里选 小（默认）/ 中（1.5 倍）/ 大（2 倍），对所有大图标视图生效。页面底部与 **我的文件** 一样有**状态栏**：左侧是选中与总数，操作结果（正在转存、已改名、已移动等）显示在右侧。
- 分组可以**重命名**，视频也可以**拖到大图标里的另一个分组**改分组；两者都只改本机显示，不动 PikPak 上的分享和文件。重命名后新收藏的同一分享者视频仍按分享者归组。分组按**显示的名字**区分：名字相同的视为同一个分组，不管它是分享者自动分组还是本地改名得来的。
- **预览**：直接播分享里的原始视频，不占网盘空间，但分享失效或被删除后就播不了。
- **完整播放**：把视频转存到**我的文件根目录下的 `Pack From Shared`** 再播，之后即使分享失效也能继续看这份副本。已经转存过的视频**不会重复转存**：直接播 `Pack From Shared` 里的那份；收藏夹里这样的视频在**大图标左下角显示绿色对勾角标**。转存前先算空间：不够时按修改时间从早到晚**永久删除** **我的视频/临时**（旧版本留下的）里的文件，还不够就永久删除 **Pack From Shared** 里的文件；整个过程不弹确认、**删除不可恢复**。仍然不够就报「空间不足」并中止，不会转存一半。
- 从**收藏夹**发起的转存（完整播放、下载）用**本机重命名后的名字**作为 `Pack From Shared` 里的文件名；重新命名已转存的视频后，下次播放会顺带把副本改成新名字。
- **下载**：在 **视频收藏夹** 选中视频点 **下载**，同样先转存到 `Pack From Shared`（已有副本直接复用），再把该副本加入下载队列，在 **传输** 里看进度。
- **播放器只需要在设置里选一次**（**设置 → 参数设置 → 播放器**）：默认 **内置播放器**，预览和完整播放都在应用内播放；选 **IINA**（仅 macOS）后，两个按钮直接把**原始链接**交给 IINA，不再经后端代理，也不再每次弹出播放方式的选择。IINA 没装时页面不会有播放器，改回内置播放器即可。
- 两个收藏夹都支持**重命名**：只改本机显示名（存 `display_title` / `display_name`），不动 PikPak 上的分享与文件；留空恢复原名。
- **视频收藏夹** 里**双击视频 = 完整播放**；单击只选中。工具栏的 **预览** 仍然播分享原片、不占空间。
- 所有文件浏览页面（**我的文件**、**回收站**、**分享浏览**、**视频收藏夹**、**分享收藏夹**）的操作提示都显示在**页面底部状态栏的右侧**，不再插入列表上方。页面顶部不再有标题行。
- **视频收藏夹** 和 **分享收藏夹** 的工具栏固定在页面顶部：内容超出可视区域时只滚动文件区域（列表的列标题也随滚动固定），底部状态栏始终可见。
- **容量使用率**显示在左侧导航最下方、**设置**的上方，每 **10 秒**自动刷新。
- 有传输任务时，容量上方会出现**传输汇总**：所有上传和下载任务合计的进度条与百分比、进行中的任务数，以及上传、下载各自的总速度（每 2 秒刷新）。它显示的是全部任务的合计，不是单个任务的进度；没有进行中的任务时不显示。


### 设置与诊断

- 账号：重新授权、解绑（解绑会删除本机凭据并清除本用户的传输任务记录，已下载文件保留）。
- 参数设置：重名策略、默认下载目录、全局同时下载数（重启后生效）、全网搜索 API Key、播放方式（代理 / 跳转）、播放器（内置 / IINA）、大图标尺寸（小 / 中 / 大）、界面语言（中文 / English）；保存按钮在卡片右上角。
- 已授权的共享文件夹：下载与上传只允许写这些目录及其子目录。
- 关于：版本、数据库大小、任务数、最近错误摘要。

## 6. 升级

直接用手动安装覆盖安装新版本。数据目录 `${TRIM_PKGVAR}` 不会被替换，绑定关系、设置、任务记录、授权目录都保留。

登录态失效时（PikPak 侧撤销授权等），应用顶部会出现常驻提示"PikPak 授权已失效"，按提示重新绑定即可。

## 7. 卸载

**应用中心 → 已安装 → PikPak → 卸载**。卸载会删除 `${TRIM_PKGVAR}`（数据库与密钥），需要重新绑定。已经下载到飞牛上的文件不受影响。

## 8. 排障

| 现象 | 处理 |
|---|---|
| 页面空白或 404 | 确认是从飞牛桌面打开（走 `/app/pikpak` 网关），而不是直接访问端口 |
| 接口返回 401 | 网关没有注入 `X-Trim-Userid`；确认从桌面内打开应用 |
| 接口返回 400 且提示身份头重复 | 网关保留了客户端伪造的 `X-Trim-Userid`，这是安全拦截，属预期行为 |
| 顶部提示"PikPak 授权已失效" | 在设置里重新绑定 |
| 绑定页一直"等待授权" | 用户码 5 分钟后过期，重新发起即可 |
| 下载到飞牛失败（403） | 目标目录不在当前飞牛用户的授权目录内，或没有写权限 |
| 上传 403 | 源文件不在授权目录内，或没有读权限 |
| 播放提示编码不支持 | 预期行为（不转码），用下载按钮保存后本地播放 |
| 完整播放提示"空间不足" | 自动清理后仍放不下：手动清理 **我的视频/临时** 或 **Pack From Shared**，或换更大的网盘 |
| 点完整播放后没有开始播放 | macOS 上准备完成后还要点 **用 IINA 播放**；确认本机已安装 IINA |
| 预览提示分享已失效 | 分享过期或被删除，只能靠之前已转存的副本（完整播放）或请分享者重新分享 |
| 全网搜索某页没有结果 | 该关键词在 Google 收录里就这么多；翻页不会变出更多，回到第 1 页换个关键词 |
| 全网搜索提示需要 API Key | 在 **设置 → 参数设置** 填写 Serper Key；提示 Key 无效则检查是否复制完整 |
| 下载速度慢 | 单用户受 PikPak 限流；并发上限可在设置里调整（重启生效） |

看日志（每个请求一行，含方法、路由、状态码、UID 与耗时，不记录令牌与签名地址；单文件 10 MiB，最多保留 5 份）：

```bash
tail -n 200 /var/apps/pikpak/var/logs/app.log
```

调试页与探针接口默认关闭。需要排查网络/网关时，在启动参数里加 `--debug`（调试页入口随之出现），排查完请去掉。

## 9. 真机验证清单

发布 1.0.0 前在一台真实 fnOS 设备上逐项确认，全部通过再打 tag：

- [ ] **安装**：手动安装 `.fpk` 成功，应用中心显示 PikPak 与正确版本号。
- [ ] **启动**：桌面打开后页面正常加载，`${TRIM_APPDEST}/app.sock` 权限为 0600，进程非 root。

## 10. 安全约定

- 只监听 `${TRIM_APPDEST}/app.sock`，不监听 TCP。
- 身份只来自飞牛网关注入的 `X-Trim-Userid`；缺失 401，重复 400，绝不从请求参数取 uid。
- 不以 root 运行。
- 令牌、设备码、签名下载地址不进日志、前端或错误提示详情；数据库与密钥文件为 0600。
- 收藏视频附带的分享访问密码与账号凭据一样加密存储，只在服务端使用，不返回前端、不写日志。
- 选 **播放器 = IINA** 时，原始 CDN 链接会交给本机播放器（浏览器只负责拉起 IINA），这是自己的选择；默认的代理播放仍不把签名地址交给浏览器。
- 默认代理播放，签名地址不离开后端；改成"跳转"模式时浏览器会直连 PikPak CDN，请自行权衡。
